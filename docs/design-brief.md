# tsuzuri-mail デザイン検討用ブリーフ（2026-11-14 時点の実装）

## 1. プロダクト概要
- 名前：tsuzuri-mail（呼び名「tsuzuri」／ロゴマークは仮で漢字「綴」1 文字を角丸の正方形に白抜き）
- 何をするもの：個人ライター 1 人が使う、メルマガ＋ステップメール（シナリオ配信）の小型マーケティングオートメーション。自前の VPS で動く。
- 利用者
  - 運営者（ライター本人・非エンジニア）：管理画面を使う。PC が主、スマホでも確認する。
  - 読者：メールを受け取り、登録フォーム・配信停止・配信設定などの小さなページを見る。ほぼスマホ。
- 規模：読者 300 人程度から始め、1 万人まで。
- 配信手段：メールのみ（Amazon SES）。LINE は将来追加の余地だけ残している。
- 目指す印象：SaaS らしく整っていて、非エンジニアが迷わない。書き手の道具としての落ち着き。

## 2. 主な機能
- 登録フォーム：キャンペーン（特典）やメルマガごとに複数作れる。専用ページ／他サイトに貼れるフォームタグ。ダブルオプトイン（確認メールのリンクで登録完了）。
- 特典（リードマグネット）：登録完了後にダウンロードリンクを配る。
- シナリオ（ステップメール）：登録後「何日後・何時」に順番に自動送信。各通に送る相手の条件（タグ・スコア・区分）。最後まで届いたらタグ付け。
- 一斉配信：メルマガ。Markdown または HTML。宛先をタグ・区分・スコア・配信の種類で絞る。プレビュー → テスト送信 → 予約／即時。
- 置き換え文字：%name%（呼び名）、%cancel%（配信停止リンク）などの組み込み＋自分で登録できる独自の置き換え文字。既定値も書ける（例：%name|読者%）。
- 配信の種類（トピック）：読者が「メルマガ本誌」「お知らせ」などを種類ごとに受け取る／受け取らないを選べる。
- タグ管理：読者にタグを付け外し。登録元フォームのタグは自動で付く。
- 読者スコア：開封・クリック・読了から独自の点数を毎晩計算し、区分（熱心／通常／低下／休眠／評価中）を決める。休眠には一斉配信を送らない、再確認メールを自動で送る、などの分岐に使う。
- 計測：開封（機械開封は除外）、クリック、Web 版の読了、バウンス、苦情。
- 法令対応：特定電子メール法（同意の記録、送信者情報ページへのリンク。メールのフッターに住所は書かない）、ワンクリック配信停止。
- 管理画面のログイン：パスワード＋認証アプリの 6 桁コード（2 段階認証）。

### 3-3. メール本文
- 最大幅 600px、白い本文、本文 16px・行間 1.9。
- Markdown なら見出し・段落・リンク・リストを自動でレイアウト。HTML なら書いたまま送る。
- フッター：送信者名、問い合わせ先、送信者情報ページへのリンク、配信停止、配信設定。
- メールソフトでは CSS 変数や Web フォントが効かないため、色はインラインで直書き（現状：背景 #f6f6f4、文字 #222）。デザインシステムの色にはまだ合わせていない。

## 4. 今のデザインシステム（tsuzuri、2026-11-14 にムードボードに合わせて改訂）
- ブランド DNA：Precision（正確さ・信頼性）／Editorial（書き手の視点）／Intelligence（データで育てる）／Minimalism（迷わない設計）／Calm Technology（続けられる心地よさ）
- 言葉：タグライン「書き手のための、メルマガ・シナリオ配信ツール」、約束「書くことを、もっと、続けられるしくみ。」
- ロゴ：深い青緑の角丸グラデーションに白い明朝の「綴」と淡い水色の払い（実装は SVG で組み直した仮のもの。正式なベクターは未受領）。名前「tsuzuri-mail」は明朝

- 実装上の決まり：色・余白・角丸はこのトークンだけを使い、値を直書きしない

## 5. 守るべき制約（デザイン案はこの範囲で）
- 読者向けページは外部のフォント・スクリプト・画像を読み込まない（読者の IP を第三者に送らないため）。Web フォントを提案する場合は「管理画面のみ」か「自分のサーバーから配る」前提で。
- メールは主要メールソフト（Gmail・Apple Mail・Outlook）で崩れないこと。インライン CSS、Web フォントに頼らない、ダークモードで読めること。
- 日本語が主。長い件名・アドレスでも崩れないこと。
- 文字と背景のコントラストは WCAG AA（本文 4.5:1 以上）。
- ライト・ダーク両方の値を出すこと。
- 管理画面は PC（幅 1280px 前後）が主、スマホ（幅 390px）でも使えること。
- 他社サービス（既存の MA ツール等）の見た目をそのまま写さない。

## 6. ChatGPT に決めてほしいこと（例）
1. ブランドの方向性：キーワード 3〜5 個、トーン（言葉づかい・ボタン文言の方針）
2. ロゴ：「綴」のマークを使い続けるか、代案
3. 色：accent を縹色のままにするか、ブランド色の案（ライト・ダーク両方、上の変数名にそろえて）
4. 書体：管理画面・読者ページ・メールそれぞれの書体と太さ、文字サイズの段階（見出し・本文・注記）
5. メールのテンプレートの見た目（ヘッダー・本文・ボタン・フッター）
6. 読者向けページの見た目（フォーム・完了・配信停止）
7. 出力形式：上の「色」と同じ変数名の一覧（--canvas, --surface, … , --font-sans, --font-mono）で返してもらうと、そのまま実装に反映できる
