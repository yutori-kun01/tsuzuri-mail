# 要件定義：打ち間違いの補正・登録経路・シナリオの分析（2026-11）

オーナーとの相談（2026-11-18）で決めた追加機能。既存の構成（PostgreSQL が正本、送信は MailProvider 越し、ダブル／シングルオプトイン）は変えない。

## 1. 主要メールの打ち間違いの補正

**目的**：シングルオプトインでも、打ち間違いのアドレスへの送信（＝バウンス）を減らし、SES のアカウントを守る。

- 対象のドメイン：gmail.com、icloud.com（me.com・mac.com）、yahoo.co.jp、yahoo.com、outlook.com・outlook.jp、hotmail.com・hotmail.co.jp、live.jp、docomo.ne.jp、ezweb.ne.jp、au.com、softbank.ne.jp、i.softbank.jp。
- 判定：ドメインが上のどれとも一致せず、どれか 1 つと「1〜2 文字違い」（入れ替え・抜け・余分を含む）なら候補を出す。`gmail.jp`・`yahoo.jp` のような、よくある取り違えは個別に対応する。`mail.com` など実在する別のサービスには出さない。
- 画面：登録ボタンを押したとき、フォームを入力内容つきで出し直し、「`a@gmial.com` ではなく `a@gmail.com` ではありませんか？」と表示する。
  - 「直したアドレスで登録する」（入力欄は直したアドレスにしておく）
  - 「入力したアドレスのまま登録する」
- 他のサイトに貼ったフォームタグから送信された場合も、同じ確認画面を出す（JavaScript は使わない。読者向けページは外部の読み込みもスクリプトも使わない方針のまま）。
- JSON で送る場合は `{ ok: false, error: "email-typo", suggestion }` を返す。

## 2. 登録経路

**目的**：X・Instagram・ブログなど、どこから登録したかを数えて、力を入れる場所を決める。UTAGE の「登録経路」に近い。

- 経路は管理画面で作る：名前（例「X プロフィール」）と、URL に付ける識別名（英小文字・数字・ハイフン。例 `x-profile`）。
- 使い方：フォームの URL に `?r=識別名` を付けて貼る。フォームタグも経路ごとにコピーできる（経路の識別名が入った隠し欄つき）。
- 記録：登録ごとの同意の記録（consents）に経路を残す。存在しない識別名は経路なしとして扱う。
- 表示：
  - 「登録経路」画面：経路ごとの登録数・登録完了数・完了率（30 日／90 日／全期間）と、フォームごとの URL。
  - シナリオの「分析」：そのシナリオのフォームから入った人を、経路ごとに数える（登録・完了・クリックした人・配信停止）。

## 3. シナリオの分析（ダッシュボード）

**目的**：どの通で反応が落ちるか、どの通のあとに配信停止が増えるかを見て、本文やタイミングを直しやすくする。

- 場所：シナリオ画面の左メニューに「分析」を足す。期間（30 日／90 日／全期間、送信日で区切る）を選べる。
- 上の数字：シナリオに入った人・最後まで届いた人（完了率）・進行中・配信停止した人。
- 通ごとの表とグラフ（横棒）：送信数、開封率（人の開封）、クリック率（人のクリック）、配信停止（この通を受け取ったあと 7 日以内に停止した人＝最後に受け取ったのがこの通の人）、バウンス・苦情。
- 目立たせる基準：
  - クリック率がシナリオの平均の半分未満 → 「反応が低い」（黄）
  - 配信停止が送信数の 0.5% 以上 → 黄、1% 以上 → 赤
  - 前の通からの送信数の減りが大きい通（進行中の人がいるため、目安として表示）
- 開封は端末の自動読み込みがあるため「目安」と表示し、判断にはクリック率を使うよう案内する。
- グラフは管理画面の中で描く（外部のグラフ用スクリプトは読み込まない）。
