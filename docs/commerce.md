# 販売（ファネル → 決済 → 商品のメール）

LP から決済して、買った人に商品のメール（続きのメール）を届けるための仕組み。
決済そのものは Stripe に任せる。カード情報はこのツールを一切通らない。

```
LP（yutorikun.site など） ──▶ Stripe の決済画面（Payment Link / Checkout）
                                   │ 支払い完了
                                   ▼
                     Stripe ──Webhook──▶ /hooks/stripe（読者向けの Worker）
                                   │ 署名を確かめる → 同じ通知は 1 回だけ
                                   ▼
          注文を記録 → 購入者を読者として持つ → 受け取る権利 → タグ → 商品のシナリオを始める
                                   ▼
               毎分の送信 ──▶ 商品のメール（%download% で商品のファイルを配る）
```

## DB の設計（`packages/db/migrations/0019_commerce.sql`）

| 表 | 役割 | 一意制約（二重処理の防止） |
|---|---|---|
| `products` | 商品。`code` を Stripe のメタデータ `tsuzuri_product` に入れて見分ける。届けるシナリオ・タグ・ファイル（R2 のキー）を持つ | `code`、`(provider, provider_price_id)` |
| `orders` | 注文（1 回の支払い = 1 行）。金額・状態・お知らせの同意の有無。**メールアドレスは持たない**（読者を消しても帳簿として残す） | `(provider, provider_order_id)`、`(provider, provider_payment_id)` |
| `payment_events` | Stripe からの通知の受け取り記録。通知の中身（氏名・メールアドレスなど）は保存しない | `(provider, provider_event_id)` |
| `entitlements` | 購入者が持つ「商品を受け取る権利」。全額返金で `revoked_at` が入る | `order_id` |

あわせて変えたもの：

- `sequences.purpose` に `product`（商品を届けるシナリオ）を足した。
- 行動履歴（`events.type`）に `purchase`・`refund`、自動化のきっかけに `purchased`・`refunded` を足した。
- `contact_tags.reason` に `purchase` を足した。

決済サービス固有の処理は `PaymentProvider`（`packages/core/src/payments/`）の中に閉じ込めている。ほかの決済サービスに替えるときは、この型の実装を足す。

## 送ってよい相手のきまり

| 読者の状態 | 宣伝のメール（メルマガ・通常のシナリオ） | 商品のメール（`purpose = product`） |
|---|---|---|
| 購入画面でお知らせに同意した | 届く（配信中の読者になる。同意の記録は `consents.method = 'purchase'`） | 届く |
| 同意していない購入者（`status = pending`） | 届かない | 受け取る権利がある間は届く |
| 配信を停止した・苦情・ハードバウンス | 届かない | **届かない**（ほかのメールと同じく、配信停止を常に優先する） |
| 全額返金された | — | 止まる（シナリオを止め、送信待ちを取り消し、ファイルのリンクも使えなくなる） |

- 一度配信を停止した人が購入画面で同意しても、自動では配信中に戻さない（フォームからの再登録で本人に確かめる）。
- 一部の返金では、受け取る権利を残す（扱いは事業者が決める）。

## Stripe とのつなぎ方

1. 管理画面の「商品と注文」で商品を作り、識別名（例 `course-a`）を決める。届けるシナリオは、使い道を「商品を届ける」にしたものから選ぶ。
2. Stripe で Payment Link（または Checkout）を作り、メタデータに `tsuzuri_product` = 識別名 を入れる。お知らせの同意を取るなら、プロモーションメールの同意を集める設定を有効にする。
3. Stripe の Webhook に `https://<読者向けの Worker>/hooks/stripe` を登録し、次の 3 つを送るようにする。
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`（コンビニ払いなど、あとから入金されるもの）
   - `charge.refunded`
4. Webhook の署名シークレットを Worker の secret `STRIPE_WEBHOOK_SECRET` に入れる。
5. テストモードで買ってみて、「商品と注文」に注文が出ること、商品のメールが届くことを確かめる。

通知の署名が合わないものは 400 で断る。処理に失敗したときは 500 を返し、Stripe に送り直してもらう（記録はトランザクションごと戻る）。

## 特定商取引法に基づく表記

管理画面の「特商法の表記」に入れた内容から、`/legal/commerce` のページを自動で作る。項目は通信販売の表記で一般に求められるもの（販売業者、所在地、電話番号、販売価格、商品代金以外の必要料金、支払方法・時期、引渡時期、返品・キャンセルなど）。所在地と電話番号は「請求があった場合には遅滞なく開示いたします」と表示する設定もある。

販売中の商品があるのに必須の項目が空だと、管理画面と `pnpm tsuzuri doctor` が知らせる。

**最終的な文言は、売る商品に合わせて事業者が確かめる**（このツールは法律の助言をしない）。次のことは、このツールでは確かめていない：

- 申込みの最終確認画面での表示（Stripe の決済画面で足りるか）
- 定期購入（サブスクリプション）を売る場合の表示

## まだ無いもの

- LP（販売ページ）。LP は `yutorikun.site` などに置き、Stripe の決済画面へのリンクを貼る。
- 定期購入（サブスクリプション）の継続・解約の扱い。
- 管理画面からの返金（返金は Stripe の画面で行い、通知で反映する）。
