# 管理画面

`https://mail.example.com/admin`（ローカルでは `http://localhost:8787/admin`）。使うのはオーナー 1 人。

## できること

| 画面 | できること |
| --- | --- |
| ホーム | 配信中の読者数、直近 7 日の登録・送信・バウンス率・苦情率、区分ごとの人数。バウンス率・苦情率が高いときや送信が止まっているときは警告を出す |
| 読者 | 検索（メールアドレス・名前・タグ・区分・状態）、詳細（スコアの内訳、タグの追加・削除、シナリオの進み具合、同意の記録、行動の履歴）、配信停止、一時停止からの再開 |
| 読者を追加 | 1 人ずつ追加（本人に確認メールを送る／同意済みとして配信中にする。どちらも同意の記録を残す）、CSV の取り込み（UTF-8・Excel の Shift_JIS、日本語の見出し可、取り込む前に人数と問題のある行を確認） |
| タグ | タグごとの人数（配信中の人数）と、使っている場所（フォーム・シナリオ・ルール・条件・宛先）。作成・名前の変更（ルールや条件に書かれた名前も追従）・別のタグへの統合・削除。フォームやシナリオが自動で作ったタグも同じように扱える。自動化のルール・ステップの条件・未送信の一斉配信の宛先で使っているタグは、消すと動きが変わるので削除できない（統合を使う） |
| 一斉配信 | 作成（Markdown か HTML）、宛先の条件（タグ・区分・スコア）と対象人数、プレビュー、テスト送信、予約・今すぐ送信、予約の取り消し、配達率・開封率・クリック率 |
| シナリオ | 作成、ステップの追加・編集・削除（日数・時刻・送る相手の条件）、プレビュー、テスト送信、ステップごとの送信数とクリック率 |
| フォーム | 作成、ページの文言・ボタン・移動先、埋め込みを許可するサイト、確認メール、他のページに貼るフォームタグ、登録数と確定率 |
| 配信の種類 | 読者が配信設定で選べる種類（例：メルマガ本誌、キャンペーン・お知らせ）の追加・編集。一斉配信とシナリオに種類を設定すると、「受け取らない」を選んだ読者には届かない |
| 置き換え文字 | 独自の置き換え文字の追加・変更・削除 |
| 配信ログ | 「メールごと」：一斉配信 1 本・シナリオの 1 通・確認メールごとに送信数・開封率・クリック率・配信停止・エラーをまとめる。件名を押すとレポート（届いてから反応まで、リンクごとのクリック、反応までの時間、開封・クリックした読者／しなかった読者、そのリンクを押した読者）。「1 通ずつ」：これまでどおり 1 通ずつの送信記録 |
| パスキー | 管理画面にパスキー（指紋・顔認証・端末の PIN）でログインするための登録・名前の変更・削除 |
| 設定 | 送信者の表示（法定表示を含む）、テスト送信先、読者スコアの重み・しきい値 |

## シナリオとフォーム

- シナリオを作ると、対になる登録フォームが自動でできる（受付は「停止」。既定ではシナリオ名と同じタグを付ける）。シナリオの画面の上に、フォームの URL・受付の切り替え・編集へのボタンがある。
- 受付は「受付を始める」「受付を止める」のボタン 1 つで切り替える（シナリオの画面、フォームの一覧、フォームの画面のどこからでも）。作ったばかりのフォームが「停止」なのは、内容を整える前に公開されないようにするため。
- フォームが受付中でもシナリオが「有効」でなければステップメールは届かない。その場合は画面に注意が出る。
- メルマガだけのフォーム（シナリオなし）は「フォーム」から作る。
- 作るときに「登録した人に付けるタグ」を選べる（名前と同じタグを新しく作る／今あるタグを使う／付けない）。
- 削除：シナリオは「基本設定」、フォームは「基本設定」のいちばん下から。送信済みの記録と同意の記録は残る（フォームを消すと、どのフォームだったかを同意の記録に書き写す）。シナリオを消すと、進行中の読者への配信と送信待ちのメールは止まり、そのシナリオを使う自動化のルールも消える。対のフォームを一緒に消すかは選べる。

## HTML 形式の本文と置き換え文字

HTML 形式では、登録済みの置き換え文字（組み込みの %name%・%cancel% など、「置き換え文字」の画面で作ったもの、%attr.キー%）だけを置き換え、それ以外の `%…%` はそのまま送る。URL の `%E3%81%82` や CSS の `width:100%` が置き換え文字と混ざらないようにするため。`%%` もそのまま残る。HTML の中で `%cancel%` という文字そのものを見せたいときは `&#37;cancel&#37;` と書く。Markdown 形式はこれまでどおり（知らない名前は打ち間違いとして保存時に止める）。

## パスキーでのログイン

1. いつもどおりパスワードと認証アプリでログインし、「設定」→「パスキー」で登録する。「この端末に登録」は今使っている PC・スマホ、「スマホに登録（QR コード）」は PC に出る QR をスマホのカメラで読み取って、スマホに保存する。
2. 次からはログイン画面の「パスキーでログイン」。PC でスマホのパスキーを使うときは「スマホで QR コードを読み取ってログイン」を押し、出てきた QR をスマホで読み取る（スマホの Bluetooth をオンにしておく）。
- 本人確認（生体認証・PIN）を必須にしているので、パスキー 1 つでパスワード＋認証アプリの代わりになる。失敗はパスワードのログインと合わせて数え、5 回で 15 分ロックする。
- パスキーは公開用の URL（`PUBLIC_BASE_URL` のホスト）に結びつく。管理画面は必ずその URL で開く。パスワードと認証アプリでのログインも引き続き使える（端末をなくしたときの入口）。

**送るタイミング**（ステップごとに 3 通り。時刻は日本時間）

| 型 | 例 |
| --- | --- |
| すぐ送る | 1 通目なら登録の直後、2 通目以降なら前の通の直後 |
| ○分後・○時間後 | 登録（前の通）から 3 時間後 |
| ○日後の○時 | 登録（前の通）から 2 日後の 8:00。時刻が空なら同じ時刻 |

ステップの一覧には「登録から約○日後」の目安も出る。

## 自動化（「○○したら△△する」）

「配信」→「自動化」でルールを作る。毎分動き、同じルールは同じ読者に 1 回だけ動く（ルール同士が呼び合って止まらなくなるのを防ぐため）。作ったあとに起きたことに対して動く。

| きっかけ（もし） | 動作（したら） |
| --- | --- |
| この文字を含むリンクを押した（人のクリックだけ。ボットは数えない） | タグを付ける／外す |
| このタグが付いた | シナリオを始める（配信中の読者だけ） |
| このシナリオを最後まで受け取った | シナリオを止める |
| このフォームで登録が完了した | |

ルールが付けたタグが次のルールのきっかけになる場合は、約 1 分後に続けて動く。リンクの候補には、一斉配信・シナリオの本文に書いた URL が出る。

## シナリオの流れ

シナリオの画面に「流れ」の図が出る。始まり（フォーム・自動化のルール）→ 各通（タイミング・送る相手の条件）→ 完了（付けるタグ・次に動くルール）。各通を押すと編集画面に移る。図は表示用で、編集はこれまでどおり下の表と各通の画面で行う。

## 一斉配信の「送り方を工夫する」

- **件名の A/B テスト**：件名 B を入れると、宛先の 10〜50%（A・B に半分ずつ）に先に送り、1〜24 時間後に人のクリック率が高い件名で残りの読者に送る（同じなら開封率、それも同じなら A）。結果は一斉配信の画面に出る。宛先が少ないと偶然の差が出やすいので、目安は 1,000 人以上。
- **読者ごとの送信時刻**：過去 180 日に人のクリックが 3 回以上ある読者は、送信日時から 24 時間以内の「よく押す時刻」（日本時間）に届く。それ以外の読者は送信日時に届く。
- 2 つは同時には使えない。

## フッター

「設定」→「フッター」で、メールの最後に付く部分のひな形を作る。一斉配信・シナリオごとに選べ、選ばなければ「既定」になる。

- 最初から「標準」（これまでと同じ 4 行）と「シンプル（リンク 2 つ）」がある。
- 送信者名 `%sender%`・配信停止 `%cancel%`・送信者情報のページ `%sender_info%`（住所と問い合わせ先を表示）は、特定電子メール法の表示のため必須。足りないと保存できない。
- フッターのリンクはクリック数・クリック率に数えない（本文のリンクだけを数える）。

## タグと配信の種類

- 一斉配信・ステップの宛先の条件、読者の詳細、読者の追加では、既存のタグをチップで押して選ぶ（読者の詳細と追加では、新しいタグも入力できる）。
- 読者一覧では、左のチェックで読者を選び、上の欄でタグを選んで「付ける」「外す」でまとめて変えられる。
- 配信の種類はカードで 1 つ選ぶ（選ばなければ配信中の全員に届く）。「配信の種類」の画面では、よくある種類（メルマガ本誌、お知らせ・キャンペーン、イベント）をボタン 1 つで追加できる。

## 読者の追加と CSV の取り込み

「読者」の右上の「読者を追加」「CSV で取り込む」から行う。特定電子メール法により、メールマガジンは同意を得た人にだけ送れる。どちらの方法でも「どのように同意を得たか」を記録し、読者の詳細画面の「同意の記録」に表示する。

**1 人ずつ追加**

- **本人に確認メールを送る（おすすめ）**：選んだフォームの確認メールが届き、本人がリンクを押すと登録が完了する。そのフォームのタグ・特典・シナリオもそのまま使われる。受付を止めているフォームでも選べる。
- **同意済みとして、すぐ配信中にする**：紙の申込書や対面などで、すでに同意を得ている人だけに使う。同意の取り方（必須）、同意した日時、タグ、始めるシナリオを指定できる。
- 既に配信中の人は、タグとシナリオだけを足す。配信停止・苦情・不達になった人は変更しない（確認メールも送らない）。本人がフォームから登録し直すことはできる。

**CSV で取り込む**

1. 1 行目を見出しにした CSV を選ぶか貼り付ける（5MB まで）。使える列：`email`／メールアドレス（必須）、`name`／名前、`consented_at`／登録日、`tags`／タグ（複数は `;` で区切る）、`attr.○○`。
2. 取り込み元の名前（タグ `src:名前` になる）と、同意の取り方を入れて「内容を確認する」。
3. 追加される人数・登録済み・ファイル内の重複・読めない行を確かめ、同意の確認にチェックを入れて取り込む。確認画面の時点では何も登録されない。

既に登録されているアドレスは変更しない（配信停止した人を勝手に戻さないため）。取り込んだ人は確認メールなしで配信中になる。CLI の `import` でも同じ取り込みができる。

## 最初の設定（ログイン情報）

パスワードと、認証アプリ（Google Authenticator、1Password など）の 6 桁コードの両方でログインする。

本番（AWS）用は、手元のターミナルで実行する（AWS にログインした状態で）：

```bash
pnpm tsuzuri admin:setup --ssm
```

ローカルで試す場合：

```bash
pnpm tsuzuri admin:setup --local
```

1. パスワード（12 文字以上）を 2 回入力する（画面には表示されない）。
2. 表示された鍵を認証アプリに登録する。登録したら鍵はどこにも保存しない。
3. 認証アプリに表示された 6 桁のコードを入力して確認する。
4. `--ssm` は SSM パラメータストア（`/tsuzuri/admin-password-hash`、`/tsuzuri/admin-totp-secret`、暗号化）に、`--local` は `.env` に保存される。

パスワードを忘れたときや、認証アプリの端末を変えたときは、同じコマンドでやり直す。

## セキュリティ

- ログインはパスワード（scrypt でハッシュ化）と認証アプリのコード（TOTP）の両方が必要。
- 5 回続けて失敗すると、15 分間ログインできない。
- ログインは 12 時間で切れる。Cookie は HttpOnly・Secure・SameSite=Strict。
- 書き込み操作は同じサイトからのものだけ受け付ける（CSRF 対策）。
- 操作はすべて `admin_audit` に記録される（ログイン、ログイン失敗、配信の予約・テスト送信、設定変更など）。
- 管理画面はほかのサイトに埋め込めない。外部のスクリプトは読み込まない。

## 画面の部品（外部ライブラリ）

- アイコン：lucide-static（ISC ライセンス）。サーバー側で SVG にして埋め込むため、外部への読み込みはありません。
- 部分更新：htmx（0BSD ライセンス）。`/admin/assets/htmx.min.js` として自分のサーバーから配ります（CDN は使いません）。一斉配信の編集画面で、入力に合わせてプレビューと宛先人数を更新するのに使っています。
- 読者向けページ（フォーム・配信停止など）はどちらも読み込みません。

## 注意

- `content/` の Markdown を `pnpm tsuzuri sync` で反映すると、同じ識別名のシナリオ・フォームは管理画面で編集した内容が上書きされる。管理画面で編集するようになったら、`sync` はシナリオ・フォームを新しく作るときだけに使う。
- テスト送信は、設定画面の「テスト送信先」にだけ送る。SES がサンドボックス中は、そのアドレスを SES で検証しておく必要がある。
- 一斉配信を予約すると、編集はできなくなる。直したいときは予約を取り消して下書きに戻す。

## データの引き継ぎ（別のサーバー・DB への引っ越し）

「設定」→「データの引き継ぎ」。

1. **引っ越し元**で「暗号化して書き出す」。読者・同意の記録・タグ・フォーム・シナリオ・一斉配信・設定・パスキーなど、アプリのデータをすべて 1 つのファイル（`.tzx`）にまとめ、AES-256-GCM で暗号化する。書き出すたびに新しい**暗号化キー**（`TZK1-` で始まる文字列）を発行し、画面に 1 回だけ表示する。キーはサーバーに残らないので、なくすとファイルは開けない。ファイルは 1 時間だけダウンロードできる。
2. **引っ越し先**に tsuzuri-mail を入れる（版は引っ越し元と同じか新しいもの）。環境変数の `TOKEN_SECRET` は引っ越し元と同じ値にする（送ったメールの配信停止・配信設定・確認・計測のリンクを使い続けるため。違うと読み込み後に注意が出る）。管理者のパスワード・認証アプリ、AWS の鍵、DB の接続先は環境変数なのでファイルには入らない。引っ越し先でも設定する。
3. 引っ越し先の「データの引き継ぎ」でファイルとキーを入れて読み込む。今のデータはすべて消えてファイルの中身に置き換わる（1 つのトランザクションで行い、失敗したら何も変わらない）。読み込んだらそのまま使える。

- 「送信記録と行動履歴も含める」を外すと小さくなる（スコアとレポートは引っ越し後のデータから数え直し）。
- VPS の標準の Caddy 設定はリクエストの上限が 6MB。ファイルがそれより大きいと、書き出し画面に注意が出る。引っ越し先の Caddyfile の `max_size` を一時的に上げてから読み込む。
- パスキーは公開 URL のホスト名に結びつくため、ホスト名が変わる引っ越しではパスワードでログインして登録し直す。

## SES の料金の目安

「設定」→「料金の目安」。月ごとに実際に送った通数（一斉配信・シナリオ・確認メール）と料金、今月の見込み（日割り）、読者数・一斉配信の回数・登録数・シナリオの通数から計算した 1 か月と 1 年の見込み、読者が増えたときの目安を出す。

- 計算は「送信通数 × 1,000 通あたりの単価」だけ。添付などのデータ量の料金・専用 IP・無料枠・税・SNS や SQS の料金は含めない。
- 単価の初期値（0.10 USD）は導入時に要件書へ記録した値。公式の料金ページ（https://aws.amazon.com/ses/pricing/）で今の単価を確かめて入れる。為替を入れると円でも表示する。
